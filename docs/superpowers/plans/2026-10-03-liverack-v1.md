# LiveRack v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native macOS FOH plugin host: any Core Audio device → racks of VST3/AU plugins → outputs, zero added latency, with crash/fault protection.

**Architecture:** JUCE 8 app. A ValueTree show model is turned into an immutable, preallocated `RenderPlan` on the message thread and swapped into the audio callback atomically. Racks run in parallel on real-time workers joined to the device's audio workgroup. Per-slot runtime state (plugin, bypass, fault flags) lives in `SlotRuntime` objects shared across plans; a watchdog bypasses faulty slots or falls critical racks back to dry. A crash-persistent "in-flight" mmap file + a guard process give relaunch with suspect plugins bypassed.

**Tech Stack:** C++20, JUCE 8 (CMake FetchContent), CMake ≥ 3.25, Xcode 26 toolchain, macOS 13+, arm64.

**Spec:** `docs/superpowers/specs/2026-10-03-liverack-design.md`

## Global Constraints

- macOS deployment target 13.0; arch arm64.
- Plugin formats: VST3 + AU on; VST2 only if `-DLIVERACK_VST2_SDK_PATH=<dir>` is given.
- Audio thread & workers: no locks, no allocation, no file I/O, no logging.
- Host adds zero buffering beyond the device buffer.
- App support dir: `~/Library/Application Support/LiveRack/`.

## Deviation from spec (decided while planning)

- Fault reporting uses per-slot atomics polled by the UI at 30 Hz instead of a FIFO (multiple worker threads would need an MPSC queue; atomics are simpler and lossless for "latest state").
- No `--recover` flag: on every launch the app checks the clean-exit marker; if absent it reads the in-flight file and starts suspect slots bypassed.
- Scanning runs in a separate console executable `LiveRackScanner` (no Dock icon), one plugin file per child process.

### Task 2: PlanBuilder

**Interfaces — Produces:**
```cpp
struct SlotSpec { std::shared_ptr<SlotRuntime> slot; };
struct RackSpec {
  juce::String id; int numChannels;          // 1 or 2
  std::vector<int> inputs;                   // device input channels (0-based)
  std::vector<juce::String> sources;         // rack ids summed into this rack (bus)
  std::vector<int> outputs;                  // device output channels
  bool critical = false, bypassed = false;
  std::shared_ptr<RackRuntime> runtime;
  std::vector<SlotSpec> slots;
};
struct PlanSpec { std::vector<RackSpec> racks; int numDeviceInputs, numDeviceOutputs, maxBlockSize; double sampleRate; };
struct BuildResult { std::unique_ptr<RenderPlan> plan; juce::String error; };
BuildResult buildPlan (const PlanSpec&);
```
`RenderPlan { std::vector<RackJob> jobs; std::vector<std::vector<int>> levels; int maxBlockSize; double sampleRate; uint64_t generation; }`; `RackJob` holds the spec copy, resolved `sourceJobs` indices, preallocated `buffer`, `dry`, `backup` (channels = max(rack ch, any slot plugin ch)), `MidiBuffer`.

**Tests (PlanBuilderTests.cpp):**
- two racks from inputs only → 1 level with both jobs.
- bus fed by two racks → 2 levels, bus in level 1, `sourceJobs` = both.
- bus of bus → 3 levels.
- cycle A→B→A → `plan == nullptr`, error contains "cycle".
- unknown source id → error contains the id.
- input channel ≥ numDeviceInputs is dropped (not an error — devices change).
- buffers sized to `maxBlockSize`.

Steps: write tests → run (fail, link error) → implement (Kahn topological levels) → run (pass) → commit.

### Task 3: Watchdog

**Produces:**
```cpp
enum class FaultReason : uint8_t { none, nonFinite, overload, overtime, stall };
struct WatchdogConfig { float hotGain = 15.85f /* +24 dBFS */; double hotSeconds = 0.05; double overtimeRatio = 0.9; int overtimeBlocks = 8; };
struct SlotHealth { int hotSamples = 0; };
struct RackHealth { int overtimeBlocks = 0; };
FaultReason checkSlotOutput (SlotHealth&, const juce::AudioBuffer<float>&, int numChannels, int numSamples, double sampleRate, const WatchdogConfig&);
FaultReason checkRackTiming (RackHealth&, double elapsedSeconds, double blockSeconds, const WatchdogConfig&);
struct FaultAction { bool bypassSlot; bool rackToDry; };
FaultAction chooseFaultAction (bool rackIsCritical, FaultReason);
```
**Tests:** NaN → nonFinite; Inf → nonFinite; +30 dBFS for 10 ms → none, for 60 ms → overload; hot counter resets on a quiet block; 7 slow blocks → none, 8th → overtime; a fast block resets; policy: non-critical nonFinite → bypassSlot only; critical nonFinite → bypassSlot + rackToDry; overtime on critical → rackToDry.

### Task 4: AudioEngine + WorkerPool

**Produces:** `class AudioEngine : public juce::AudioIODeviceCallback { void setPlan (std::unique_ptr<RenderPlan>); void collectGarbage(); std::atomic<uint64_t> heartbeat; std::atomic<bool> inCallback; float getCpuLoad(); int getDropouts(); }`; `class WorkerPool { void start (int numThreads, juce::AudioWorkgroup); void stop(); template<F> void parallelFor (int n, F&&); }`.

Per block: load plan (acquire), publish `seenGeneration`; copy device inputs → job buffers (mapping, clear extra channels); for each level `parallelFor` → `processRack`; clear outputs; sum each non-faulted job buffer into its outputs. `processRack`: copy dry; for each slot (skip user-/fault-bypassed): copy backup, adapt channels (mono rack + stereo plugin: duplicate in, average out), mark `InflightLog`, `processBlock`, unmark, `checkSlotOutput` → on fault apply `chooseFaultAction`, restore backup; then `checkRackTiming`; if rack `dryFallback` → copy dry into buffer; update meters.

Plan retirement: `setPlan` swaps, pushes old into `retired` with the new generation; `collectGarbage()` (message thread timer) deletes retired plans whose generation ≤ `seenGeneration` or when the device is stopped.

**Tests (EngineTests.cpp)** using dummy `AudioProcessor`s (Gain, NaNMaker, Sleeper) wrapped as `AudioPluginInstance` and a manual call to `audioDeviceIOCallbackWithContext`:
- gain ×2 rack input 0 → output 0 doubles the signal.
- two racks summed into the same output add.
- bus of two racks → output = sum after bus gain.
- NaNMaker on non-critical rack → output equals pre-slot signal, slot fault = nonFinite.
- NaNMaker on critical rack → output equals dry input, rack dryFallback = true.
- user-bypassed slot is skipped.
- parallel run with 3 workers gives identical output to single-threaded.

### Task 7: PluginHost + OutOfProcessScanner + LiveRackScanner

`PluginHost` owns `AudioPluginFormatManager`, `KnownPluginList` (persisted XML), `std::map<String, std::shared_ptr<SlotRuntime>>`; listens to the show ValueTree; creates instances async for new SLOTs (restoring state), prepares them for the current device, builds `PlanSpec` and calls `engine.setPlan` (debounced via `AsyncUpdater`). `captureStates()` writes each plugin's state into its SLOT. Scanner child: `LiveRackScanner <format> <fileOrId> <outFile>` writes `<PLUGINS>` XML; parent waits 30 s, failure → returns false (file goes to the failed list). Manual check: scan, list includes `Defeedback`.

### Task 8: Session safety (SessionGuard + LiveRackGuard)

Clean-exit marker written in `shutdown()`, deleted at startup. Startup: if marker missing and autosave exists → read InflightLog suspects, set those SLOT `faultBypassed=true` and show a banner. Autosave debounced 500 ms on model change + every 30 s (with `captureStates`). Stall detector: 250 ms timer; `inCallback && heartbeat unchanged for 1 s` → autosave + `std::abort()`. Guard: spawned via `posix_spawn` with `--pid <pid> --app <bundle>`; kqueue NOTE_EXIT; if marker absent → `open -n <bundle>`; give up after 3 relaunches in 60 s. Manual check: `kill -9` the app → it relaunches with show restored.

### Task 9: UI

Dark flat LookAndFeel. `MainComponent`: TopBar (device, SR, buffer, latency ms, DSP %, dropouts, Bypass all, Settings), left `RackList`, right `RackView` or `RoutingView` (tab). `RackView`: slot rows (name, latency samples→ms, bypass toggle, Edit, fault label + Re-arm, remove, reorder up/down), "+ Add plugin" → `PluginBrowser` (search box + list from KnownPluginList, double-click adds). Rack header: name, mono/stereo, Critical toggle, input & output channel pickers, source racks picker (bus). `RoutingView`: grid of toggles inputs×racks and racks×outputs. `SettingsView`: `AudioDeviceSelectorComponent` + `PluginListComponent` with the custom scanner. 30 Hz timer polls runtimes for meters/faults.
